# EESSI-jupyterlab-docker

Files to build a docker image running an EESSI-enabled jupyterlab server.
The image is tailored to be able to run a set of notebooks provided in the respective [AITW notebooks repo](https://github.com/AI-TranspWood/jupyter-notebooks)
through the [AITW docker extension](https://github.com/AI-TranspWood/jupyter-docker-extension).

## Requirements

Due to normal restrictions to volume mounting in docker, the image needs to be run with `--privileged` flag.
This is required for CVMFS to be able to mount the filesystem.

## Features

### Image

- Build a venv for jupyterlab with extra packages for launcher/notebook support:
  - [jupyter_app_launcher](https://github.com/trungleduc/jupyter_app_launcher): Allow customization of the jupyterlab launcher to add the AITW notebooks as clickable icons.
  - [jupyter_archive](https://github.com/jupyterlab-contrib/jupyter-archive): Allow downloading of directories as zip files.
  - [voila](https://github.com/voila-dashboards/voila): Used in conjunction with `jupyter_app_launcher` to allow cleaner rendering of the notebooks without displaying the source-code of the cells.
- Apply an [EasyBuild patch](https://raw.githubusercontent.com/easybuilders/easybuild-easyconfigs/refs/heads/develop/easybuild/easyconfigs/j/jupyter-server/jupyter-core-5.8.1_fix_jupyter_path.patch) to `jupyter-core` to enable recognizing EB-specific environment variables.
- Start the server as the non-root user `eessi-user`
- `entrypoint.sh`:
  - Start as root to be able to mount the CVMFS filesystem
  - Download the AITW notebooks from the [AITW notebooks repo](ttps://github.com/AI-TranspWood/jupyter-notebooks.git) if not present
- Start the jupyterlab server as `eessi-user` with EESSI initialized but no version loaded and allowing to more aggressively cull idle kernels

### Compose

A `docker-compose.yml` file is provided to test the image either with the main branch of the notebooks or with a local development version that can be enabled by mounting a local directory with the notebooks into the container.

#### Volumes

By default 2 volumes are created to:
- Store the CVMFS cache to avoid downloading the same files multiple times
- Save the `eessi-user` home directory to persist the notebooks and any changes made to them and outputs generated by the notebooks.

#### Usage

- Run the container with `docker compose up --build -d`
- Use `docker compose logs` to get the URL with the token to access the jupyterlab server.
- Use `docker compose down` to stop the container and add `-v` to remove the created volumes as well.
